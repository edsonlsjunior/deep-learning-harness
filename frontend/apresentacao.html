01 · LLMs

LLMs

O motor que prevê o próximo token

Antes de falar de agentes, vamos abrir o modelo: pesos, tokens, contexto e controles de geração.

pesostokenscontexto
Nova abertura da seção. Mostre a imagem como uma metáfora: fragmentos entram, passam por muitas camadas e uma previsão sai. Diga que vamos entender o motor antes de acoplar o harness, que dá ao motor ferramentas, memória e permissões.

01 · Fundamentos

O que é um LLM

entrada (tokens)“A capital da França é”
→
uma rede neuralTransformerbilhões de pesos treinados
→
próximo token“ Paris”

…e repete: o token gerado volta para a entrada (geração autorregressiva). É o mesmo Transformer da Aula 3, só que gigante e treinado em muito texto.

função

Só prevê texto

Recebe uma sequência de tokens, devolve a distribuição do próximo. Tudo que ele “faz” é gerar texto.

pesos

Conhecimento congelado

O que ele sabe está nos pesos, até a data de corte do treinamento. Não consulta nada sozinho.

sem estado

Não lembra de nada

Cada chamada começa do zero. A “memória” de um chat é o histórico reenviado a cada vez.

Ligar com a disciplina: um LLM é um Transformer (decoder) treinado para prever o próximo token. É uma função pura: tokens entram, probabilidades saem. Guardar três propriedades, porque o harness existe justamente para compensar cada uma: só gera texto (não age), conhecimento fixo (não consulta), sem estado (não lembra).

01 · Por dentro do LLM

“Parâmetro” pode significar duas coisas

aprendidos no treinamento

Pesos do modelo

Bilhões de números ajustados durante o treinamento. Eles determinam como os tokens são transformados e quais continuidades recebem maior probabilidade.

Ex.: um modelo “7B” possui aproximadamente 7 bilhões de parâmetros.
escolhidos durante o uso

Configurações de geração

Valores que controlam a execução de cada pedido, quando o produto e o modelo permitem.

Ex.: limite de saída, esforço de raciocínio e aleatoriedade.
Abra perguntando: quando alguém diz “o modelo tem 70 bilhões de parâmetros”, está falando da mesma coisa que temperatura 0,2? Não. A palavra aparece nos dois contextos, mas os pesos foram aprendidos no treinamento e as configurações controlam uma execução.

01 · Por dentro do LLM

O que significam bilhões de parâmetros

7B

Cerca de sete bilhões de valores numéricos aprendidos.

Eles não são sete bilhões de fatos armazenados. O conhecimento aparece distribuído nas relações entre muitos pesos.
Tamanho16 bits4 bits
7 bilhões≈ 14 GB≈ 3,5 GB
70 bilhões≈ 140 GB≈ 35 GB

Estimativa apenas para armazenar os pesos. A execução também usa memória para contexto, ativações e estruturas do sistema.

Modelo maior não garante melhor resultado. Dados, arquitetura, treinamento, especialização e ferramentas também importam.
A conta é parâmetros × bytes por parâmetro. Em 16 bits, cada parâmetro ocupa aproximadamente 2 bytes. Em 4 bits, aproximadamente meio byte. A quantização reduz memória ao representar os pesos com menor precisão. Fonte: https://huggingface.co/docs/transformers/quantization/overview

Tokens: a unidade que o modelo processa

Antes de entrar na rede, o texto passa por um tokenizador.

program ação com IA

Ilustração. A divisão exata depende do modelo, do vocabulário e do idioma.

Um token pode ser palavra, parte de palavra, pontuação ou espaço associado

Entrada e saída consomem tokens

Ferramentas, schemas, imagens e arquivos também ocupam contexto

Idiomas diferentes podem gerar contagens diferentes

Em inglês, uma aproximação comum é 1 token ≈ 4 caracteres. Para português, código e textos técnicos, conte de verdade quando o limite importar.
A divisão mostrada é apenas visual. Não afirme que todo modelo tokeniza a frase daquele jeito. A OpenAI explica que token pode representar caractere, parte de palavra, palavra inteira ou pontuação, e que idiomas variam. Fonte: https://help.openai.com/en/articles/4936856-understanding-and-counting-tokens

01 · Durante a geração

Parâmetros que controlam uma execução

Temperatura

Controla o quanto a escolha do próximo token varia.

Top-p

Reduz o conjunto de opções consideradas durante a amostragem.

Limite de saída

Define o máximo de tokens da resposta.

Esforço de raciocínio

Define quanto processamento o modelo dedica antes de responder.

Nem todo modelo expõe todos os controles. Produtos mais novos podem administrar alguns deles automaticamente.
Evite ensinar temperatura como botão universal. Algumas famílias recentes não aceitam temperatura, top-p ou top-k fora do padrão. O conceito continua útil, mas a disponibilidade depende do modelo e do endpoint. Fontes: https://help.openai.com/en/articles/5072518-controlling-the-length-of-openai-model-responses e https://docs.anthropic.com/en/docs/about-claude/model-deprecations

02 · Limites do LLM

LLM “puro”: texto entra, texto sai

# uma chamada direta ao modelo{
  "model": "claude-…",
  "messages": [{ "role": "user",
    "content": "Treine um MLP no XOR e me
                diga a acurácia." }]
}
# resposta
{ "content": "Claro! Aqui está o código em
  PyTorch: … Ao executar, você deve obter
  acurácia próxima de 100%." }

Não executa nada: o código não roda

Não vê seus dados, arquivos ou sistemas

Não lembra: você reenvia o histórico

Pode “chutar” o resultado (“deve dar ~100%”)

Quem faz o loop é você: copiar o código, rodar, colar o erro de volta, repetir.
Mostrar que, sem nada em volta, o modelo responde ao pedido “treine” com texto que descreve um treino. Ele não tem como treinar. O usuário vira o harness manual: executa, observa, devolve o resultado. Perguntar à turma: quais partes desse trabalho manual poderiam ser automatizadas? Essa é a definição de harness.

03 · Harness

Harness: tudo em volta do modelo

Agente = LLM + Harness

Harness é “arreio”: o cavalo tem a força, o arreio a direciona para puxar a carroça. O modelo decide; o harness executa, informa, limita e registra.

loop

Chama o modelo de novo após cada ação

ferramentas

Dá “mãos”: funções que de fato executam

contexto

Instruções, regras e conhecimento do domínio

memória

Histórico, sessões, arquivos de memória

permissões

O que pode rodar, e o que exige aprovação

logs

Ver o que o agente fez, quanto custou

Cada peça compensa uma limitação do slide anterior: loop + ferramentas resolvem “não age”; contexto resolve “não conhece meu domínio”; memória resolve “sem estado”; permissões e logs existem porque agora o modelo age de verdade, e precisamos de limites e auditoria.

03 · Harness

O loop agêntico

1 · modeloLê o contexto e decide o próximo passo
→
2 · modeloPede uma ferramentatool_use
→
3 · harnessExecuta a função de verdade
→
4 · harnessDevolve o resultado ao contextotool_result
↺ Volta ao passo 1 quantas vezes forem necessárias. Quando o modelo responde sem pedir ferramenta, o loop termina.
# o núcleo de qualquer harness, em pseudocódigo
mensagens = [system_prompt, pedido_do_usuario]
while True:
    resposta = llm(mensagens, ferramentas=descricoes())
    if not resposta.tool_calls: return resposta.texto
    for chamada in resposta.tool_calls:
        if permitido(chamada): mensagens.append(executar(chamada))
Esse é o coração. Importante: o modelo nunca executa nada. Ele emite um pedido estruturado (nome da ferramenta + argumentos em JSON). Quem executa é o harness, que depois devolve o resultado como mais uma mensagem. O modelo então “vê” o resultado e decide de novo.

03 · Harness

Do que um harness é feito

contexto

System prompt

Quem é o agente, regras e conhecimento do domínio. Ex.: CLAUDE.md, --append-system-prompt.

ação

Function tools

Funções descritas por nome + descrição + JSON Schema. O modelo pede; o harness executa.

protocolo

MCP

Padrão para plugar ferramentas de qualquer servidor em qualquer cliente de IA.

conhecimento

Skills

Pacotes de instruções (e scripts) carregados só quando a tarefa pede.

estado

Memória e sessões

Histórico da conversa, --resume, arquivos de memória entre sessões.

segurança

Permissões e hooks

O que roda sem perguntar; scripts que interceptam ações antes/depois.

delegação

Subagentes

Outro agente, com contexto próprio, para uma subtarefa isolada.

visibilidade

Observabilidade

Eventos em stream, custo e turnos para saber o que o agente fez e por quê.

Não precisa decorar: a ideia é reconhecer as categorias. Function tools são a mecânica básica de ação; MCP é a forma padronizada de entregar tools (e outros recursos) a um cliente; skills são contexto sob demanda, para não lotar o prompt; permissões e hooks controlam o risco.

Ex.: train_model, create_project. Descobertas via tools/list, chamadas via tools/call.

Dados para leitura

Conteúdo endereçado por URI que o cliente pode anexar ao contexto. Ex.: lab://guia.

Modelos de mensagem

Instruções reutilizáveis que o servidor oferece ao usuário (ex.: “comparar treinos”).

Escreve-se o servidor uma vez e qualquer cliente MCP o usa, como um conector USB-C para ferramentas.
Antes do MCP, cada aplicação de IA tinha seu formato próprio de ferramenta. Com o MCP, o servidor anuncia suas ferramentas (nome, descrição, schema) e o cliente as oferece ao modelo. No nosso caso o transporte é stdio: o Claude Code inicia o server.py como subprocesso e conversa por stdin/stdout.

training.start() faz:

1Valida: modelo e base existem e são do mesmo projeto
2Checa se a arquitetura serve para a tarefa da base
3Mescla hiperparâmetros: comuns ← padrão da arquitetura ← os seus
4Grava a execução (queued) no SQLite
5Dispara uma thread de treino e retorna na hora
Mostrar no código: backend/app/main.py (rota) e backend/app/training.py, função start. Note que o treino é assíncrono: a rota devolve o id da execução imediatamente e a thread atualiza history/metrics no banco a cada época. É isso que a UI desenha ao vivo. A rota /wait serve para quem quer bloquear até terminar, e é ela que o MCP usa.

04 · Nível MCP

A mesma função como ferramenta MCP

backend/mcp_server/server.py (resumido)@mcp.tool()
async def train_model(model_id: int, dataset_id: int,
        epochs: int | None = None, lr: float | None = None,
        optimizer: str | None = None, …, wait_seconds: int = 120) -> str:
    """Treina um modelo numa base (ambos do mesmo projeto).
    Hiperparâmetros omitidos usam o padrão da arquitetura.
    `optimizer`: adam | sgd | rmsprop …
    Aguarda até `wait_seconds` pelo fim do treino; se não
    terminar, retorna o id para consultar com `get_run`."""

    run = await call("POST", "/api/runs", json={…, "hyperparams": hp})
    run = await call("GET", f"/api/runs/{run['id']}/wait", …)
    return dump(run_summary(run))
